01 · 方案对比

普通投屏，撑不起一个机房

投屏软件按整屏重发，几十台就开始卡；广播方案又容易被交换机的风暴抑制限速。把画面切块做增量，用组播把一份数据送到所有接收端。

关注点 普通投屏 / 直播 屏幕广播
传输内容 每帧整屏重发 只发变化的 64×64 瓦片
网络方式 单播多份，或广播泛洪 组播 + IGMP Snooping，可切广播
上百台规模 带宽与交换机端口吃紧 静态画面每台 < 1 Mbps
自适应 分辨率与帧率固定 按在线台数自动降档
跨系统 常常只支持一端 Windows 与 macOS 可混用
账号与云端 需要登录或安装插件 局域网直连，无账号
02 · 工作方式

一帧画面，四步到达

从采集到显示，整条链路都在局域网内完成。没有云端中转，也不需要额外运行环境。

  1. 01

    采集

    教师机抓取屏幕，按上限缩放到 1920 / 1600 / 1280，保持原始比例。

  2. 02

    差分

    与上一帧比较，只保留变化的 64×64 瓦片，单独压缩。

  3. 03

    组播

    一份数据流发往组播地址，由交换机复制给所有订阅端口。

  4. 04

    拼装

    接收端把瓦片贴回画面，每 5 秒的关键帧负责自愈与补画面。

03 · 瓦片增量

只发变化的那几块

每帧与上一帧做差分，变化的区域单独压缩成一个 UDP 包。画面静止时几乎不发数据；翻页、打字、移动光标，都只占几个块。

04 · 自适应

人多了，自动降一档

接收端每 3 秒向发送端上报一次心跳，发送端显示在线台数，并在台数跨过阈值时自动调整分辨率与帧率。

05 · 跨平台

教师机和学生机，不必是同一个系统

发送端与接收端都在 Windows 和 macOS 上提供，协议一致。混合部署时，两端照常互相识别。

Windows

x64 · Windows 10 / 11
  • 单文件 exe，无需安装 Python
  • Per-Monitor V2 DPI 感知，高分屏不糊
  • 学生机放行 UDP 22222；教师机可选 22223
  • 设置面板内置，参数随程序目录保存

macOS

Apple 芯片 · macOS 13+
  • 发送端与接收端均为独立 App
  • 发送端首次运行需授予“屏幕录制”权限
  • 接收端全屏显示，Esc 退出
  • Intel Mac 可从源码自行构建

混合部署：Windows 教师机 → macOS 学生机，或 macOS 教师机 → Windows 学生机，同一套协议即可工作。

06 · 部署

三步，把画面送到每一台

不需要安装服务端，也不需要账号。分发两个程序，放行端口即可。

  1. 教师机开始广播

    运行发送端，点击「开始广播」。默认组播，也可以在设置里改为广播。

  2. 学生机接收

    运行接收端，自动全屏接收；按 Esc 退出。分辨率一致时逐像素 1:1 显示。

  3. 按机房调整

    在「设置」里改采集宽度、帧间隔与关键帧间隔，或关闭自动调节。

防火墙 · 管理员命令
# 学生机：接收广播 netsh advfirewall firewall add rule name="UDP屏幕广播" dir=in action=allow protocol=UDP localport=22222 # 教师机：统计在线台数（可选） netsh advfirewall firewall add rule name="UDP屏幕广播心跳" dir=in action=allow protocol=UDP localport=22223
07 · 透明

不上云，不埋点，代码可查

画面只在局域网内传输。没有账号、没有服务器、没有统计埋点，断网也能用。

局域网直连

广播、心跳、显示全部在同一子网完成，不经过任何云端服务。

MIT 开源

源码、构建脚本与 CI 全部公开，可自行审计、修改、二次分发。

参数可控

组播与广播可切换，分辨率与帧率可调，设置随程序目录一起带走。

08 · 常见问题

部署前，先看看这些

没找到答案？在 GitHub 上提交 issue，或直接查看源码与构建说明。

提交问题
一间教室能带多少台？

有线千兆、同一 VLAN 的机房，60–100 台是常规规模；静态课件时每台带宽通常低于 1 Mbps。百兆网络建议把采集宽度调到 1280，或把帧间隔调到 1.0 秒。

需要连接互联网吗？

不需要。广播、心跳、显示全部在局域网内完成，没有云端服务，也没有账号体系。

收不到画面怎么排查？

先确认两端在同一子网，再检查学生机是否放行入站 UDP 22222。如果交换机禁用了组播，在发送端「设置」里改为广播；同一网段只能运行一个发送端。

macOS 提示无法截取屏幕？

发送端需要“屏幕录制”权限：系统设置 → 隐私与安全性 → 屏幕录制，勾选后重新启动 App。接收端不需要这个权限。

在线接收端一直显示 0 台？

说明教师机没有收到心跳：可能是教师机未放行入站 UDP 22223，或学生端是旧版本。广播本身不受影响，只是自动调节不会生效。

可以自己改代码吗？

可以。项目以 MIT 协议开源，源码、单元测试和打包脚本都在 GitHub 上。修改协议时请同步更新两端，避免版本不兼容。
